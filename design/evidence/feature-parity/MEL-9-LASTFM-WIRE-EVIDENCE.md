# MEL-9 — Last.fm Configured-State Wire Qualification (Partial)

**Status:** Partial — real-provider wire-contract evidence. The real-account
link/unlink and live scrobble legs remain open (operator-controlled Last.fm
account required; production settings have `scrobbling.lastFm.Enabled=false`).

**Candidate:** repository main at the evidence commit; dev topology
(`batman.home.arpa`, debug build, dev PostgreSQL 18).
**Evidence date:** 2026-10-19.
**Harness:** `scripts/qualify_lastfm_wire.py` (redacted evidence JSON:
`melodee-lastfm-wire-evidence/v1`; generated live from the legacy settings
export). Unit coverage: `tests/python/test_qualify_lastfm_wire.py`.

## What was exercised against the real provider

All probes used the production-configured Last.fm API credentials
(`scrobbling.lastFm.apiKey`/`sharedSecret`, imported verbatim into the dev
instance via `melodee-cli config import`) against
`https://ws.audioscrobbler.com/2.0/`. No credential is printed, logged, or
committed; error codes/messages are public API responses.

| Probe | Observed wire behavior | Interpretation |
|---|---|---|
| `auth.getToken` (unsigned GET) | HTTP 200, success envelope | API key is valid and provider reachability confirmed |
| `auth.getSession` (signed, deliberately invalid token) | HTTP 403, **error 4** "Unauthorized Token - This token has not been issued" | Link-attempt failure contract; code 4 is a clear-session trigger (ADR-0004 set {4,9,10}) |
| `track.scrobble` (signed **POST**, bogus session key) | HTTP 403, **error 9** "Invalid session key - Please re-authenticate" | Invalid-session scrobble rejection; no scrobble was written to any account; code 9 is a clear-session trigger |
| `auth.getSession` (unsigned) | HTTP 400, **error 6** "Invalid parameters - missing a required parameter" | Provider rejects unsigned auth attempts; signature presence is enforced before auth evaluation |
| Unreachable endpoint (closed local port) | transport_error classification, no hang | Connection-failure path classifies cleanly under the bounded timeout |

## Key findings

1. **The Rust signature construction is provider-accepted.** Both signed
   probes produced session/auth errors, not error 13 ("Invalid method
   signature"): the sorted name+value concatenation with the shared secret
   appended (MD5 hex, `lastfm.rs build_api_signature`, excluding `format`
   and `api_sig`) matches the real provider's expectations.
2. **The clear-session trigger set is confirmed on the real wire.** Invalid
   link token → 4; invalid scrobble session → 9. Both are members of the
   ADR-0004 clear set {4, 9, 10} that the Rust dispatcher implements
   (`is_invalid_session`); the provider "Please re-authenticate" message
   matches the link-clearing/re-link-only-recovery contract.
3. **Write-method enforcement confirmed:** GET `track.scrobble` is rejected
   ("must use POST method"); the Rust client's `signed_post` path is correct.
4. **Graceful disable is the production shape:** production C# settings had
   `scrobbling.lastFm.Enabled=false` with credentials stored; the dev
   instance reproduces exactly that configured state (credentials present,
   scrobbling disabled), so no scrobble traffic is generated by this
   qualification.

## Remaining for full MEL-9 acceptance

- **Real-account link/unlink and live scrobble/now-playing:** requires an
  operator-controlled Last.fm account (and enabling scrobbling) — the
  operator must authorize the account used; no credential is present in the
  settings export for this leg.
- **Forced rate limit:** cannot be exercised without abusive load; the
  mock suite (`apps/melodee-server/tests/lastfm_scrobble.rs`) covers
  rate-limit handling deterministically and it is recorded as unexercised in
  the wire-evidence JSON.
- Retry/no-retry semantics documentation check and parity-ledger linkage
  (already recorded; final closeout under MEL-18 after operator legs).
