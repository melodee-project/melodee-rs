## 2. melodee-player (Android) — 13 routes

All traffic is native API v1 (`<scheme>://<host>[:port]/api/v1/`). **Zero OpenSubsonic routes are
used.** Auth is `Authorization: Bearer <jwt>` on API calls; media and image fetches carry **no
auth headers at all**.

| # | Method | Route | Used for |
|---|---|---|---|
| 1 | POST | `/api/v1/auth/authenticate` | login (`userName` XOR `email` by `@` presence) |
| 2 | POST | `/api/v1/auth/refresh-token` | 401 retry only; `X-Refresh-Request: true` header suppresses Bearer |
| 3 | GET | `/api/v1/system/info` | version gate ≥ 1.2.0 before every login |
| 4 | GET | `/api/v1/user/me` | profile |
| 5 | GET | `/api/v1/user/playlists` | home/playlists/**Android Auto browse** — query: `page` + **`limit`** |
| 6 | GET | `/api/v1/playlists/{apiKey}/songs` | playlist detail, Auto browse, lazy queue pagination — query: `page` + **`pageSize`** |
| 7 | GET | `/api/v1/search/songs` | Auto voice/text search (`q`, `page`, `pageSize`, `filterByArtistApiKey?`) |
| 8 | GET | `/api/v1/artists` | Auto structured search artist resolution (`q`) |
| 9 | GET | `/api/v1/artists/{id}/songs` | Auto artist browse |
| 10 | GET | `/api/v1/artists/{id}/albums` | artist detail |
| 11 | GET | `/api/v1/albums/{id}/songs` | album detail (no query params) |
| 12 | POST | `/api/v1/songs/starred/{apiKey}/{isStarred}` | favorite toggle incl. Auto/notification — **path-encoded bool, no body** |
| 13 | POST | `/api/v1/scrobble` | nowPlaying @10 s, played @50 %; body carries **both** `scrobbleTypeValue` (int) and `scrobbleType` (string) |

Opaque server URLs consumed verbatim: `Song.streamUrl` (ExoPlayer `MediaItem.fromUri`,
CacheDataSource + DefaultHttpDataSource, 200 MB disk cache, no explicit Range headers) and
`*.thumbnailUrl`/`imageUrl` (Coil + MediaSession). **The client never constructs stream or image
URLs** — whatever self-authenticating shape the server embeds is a hard compatibility requirement.

Not used: logout, register, rating endpoints, queue endpoints, shares, genre routes, any
`/rest/` route. Logout is local token clearing only.

### Android Auto paths (PRD-STREAM-003 relevant)

`MusicService` (`MediaBrowserServiceCompat`): browse tree root → `playlists` →
`playlist_<uuid>`; voice search resolves "title by artist" via `/artists?q=` then
`/search/songs?filterByArtistApiKey=`; favorites toggle and scrobbling ride the same routes as
the phone UI. Stream/artwork reach Auto through the same server-provided URLs.

## 3. MeloAmp (desktop) — 98 routes

Auth is `Authorization: Bearer <jwt>` (axios interceptor); on 401 the interceptor POSTs
`/auth/refresh` once and retries. Stream playback appends **`?jwt=<token>`** to the
server-provided `streamUrl` for `<audio>` elements. The queue is **entirely client-side**
(zustand/localStorage); `/api/v1/queue` is never called. Declared-but-unused: all `/rest/`
podcast routes, `auth/logout`, `auth/revoke`, `auth/password-reset/*`, `songs/random`,
`songs/{id}/lyrics`, `search/suggest`, `search/similar`.

Used route groups (route-by-route table with file:line evidence in
`native-client-usage.json`):

- **Auth/system:** authenticate, refresh (legacy JWT endpoint), system/info (unauthenticated
  version gate), system/stats.
- **Browse:** artists (list/recent/detail/albums), albums (list/recent/detail/songs), songs
  (list/detail), genres (list, genres/{id}/songs).
- **Playlists:** user/playlists, detail, songs, create, update, delete, add-songs, reorder,
  image upload; smart playlists CRUD + evaluate.
- **Search:** POST /search, GET /search/songs, POST /search/advanced.
- **Star/hate/rating:** path-verb routes for songs, albums, artists
  (`/songs/starred/{id}/{bool}`, `/songs/setrating/{id}/{0-5}`, etc.).
- **User library:** user/me, user/{entity}/liked|disliked|top-rated|rated (entity is a literal
  segment: songs|albums|artists), user/last-played.
- **Scrobble:** POST /scrobble (nowPlaying @10 s; played @70 %).
- **Shares, themes, equalizer, analytics, charts, recommendations, requests (+comments,
  activity), playback-backend, endpoints, admin/users, artist-lookup** — used by MeloAmp but
  outside the critical playback/browsing/auth path; classified `client-used-uncaptured` in the
  unified inventory for later-phase capture.

## 4. Cross-client findings

1. **`limit` vs `pageSize` inconsistency is contract.** `/user/playlists` takes `limit`;
   `/playlists/{id}/songs` takes `pageSize` (Android uses both). Both are captured in golden
   scenarios.
2. **Star/rating is path-encoded**, not body-encoded (`/songs/starred/{uuid}/{true|false}`).
3. **Stream URLs must be self-authenticating absolute URLs.** Neither client attaches
   credentials to media requests; MeloAmp appends a *tolerated* `?jwt=` query parameter.
4. **Artwork URLs must be anonymously fetchable.** The `/images/{type}_{apiKey}/{size}` route
   is served by the **OpenSubsonic** `ImageController` but consumed by both native clients — a
   cross-surface dependency recorded in the unified inventory.
5. **MeloAmp add-to-playlist is broken against this baseline.** It posts
   `{ "songIds": [...] }` to `/playlists/{id}/songs`, but the server binds `[FromBody] Guid[]`
   (a bare array). Object form → 400 model-binding envelope; correct bare-array form → **500**
   (server-side null-navigation bug in `PlaylistService.AddSongsToPlaylistAsync`). No working
   add-songs form exists at the baseline. Captured as
   `catalog-playlist-crud/add-songs` and `add-songs-meloamp-shape`.
6. **MeloAmp never calls `auth/logout`** (declared helper, no call sites); Android has no
   logout at all. Server-side logout semantics are captured regardless (auth flow evidence).
