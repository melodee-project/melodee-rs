# Phase 0 Evidence — OpenSubsonic Compatibility Capture

**Issue:** FIRST-10-ISSUES.md Issue 6 — Capture OpenSubsonic critical path and negative behavior
**Requirements:** PRD-API-OS-001 through PRD-API-OS-007, PRD-STREAM-002
**Baseline:** legacy commit `4028b58dbd3302ed431e2c5b32d9dde5634db218` (authoritative SHA);
server version `2.2.0`; DB migration head `20260714155936_AddDeleteSourceResidueAfterIngestSetting`
**Recorded:** 2026-08-07/08
**Golden evidence:** `compatibility/opensubsonic/golden/` (11 directories, 177 captures, each with
`provenance.json`). **Inventory:** `compatibility/opensubsonic/contracts/route-inventory.json`
(81 endpoints). OpenSubsonic is a distinct surface; nothing here is shared with native v1 DTOs.

## 1. Method

Same oracle, fixture catalog, and capture engine as Issue 5 (`scripts/legacy_oracle.py`,
`scripts/capture_baseline.py` schemaVersion 2). Two consecutive full runs compare with **zero
differences after declared normalization** across all 14 scenario files (3 native + 11
OpenSubsonic, re-validating Issue 5 golden in the same pipeline). Enforced (non-bypassed)
authentication is captured by running the oracle with `UseForwardedHeaders=true` and presenting
`X-Forwarded-For: 203.0.113.7` + `X-Forwarded-Host: capture-fixture.example.test` — both
synthetic — which defeats the localhost and baseUrl auth bypasses without modifying the server.
The fixture user's OpenSubsonic secret is seeded to a known synthetic value through the same
AES-GCM `SecretProtector` the server uses; the md5 token is computed at capture time and never
persisted (env injection + capture-time unsubstitution; enforced by tests).

**Pipeline fixes made for this issue:** `legacy_oracle.py stop` now blocks until the process
group exits (readiness could pass against a dying instance); the capture pipeline reseeds **and
restarts** the server per scenario file (the server caches user/song detail rows); scenario
files iterate conditionally (podcast disabled phase toggles `podcast.enabled` and restores it).

## 3. Authentication findings (16 golden steps)

| Behavior | Evidence |
|---|---|
| Valid u/t/s | 200; token = `md5(opensubsonicSecret + salt)`; comparison case-insensitive (uppercase accepted, captured) |
| Valid u+p plain and `enc:` hex | 200 (bcrypt verify) |
| Invalid username / token / malformed token / missing auth / t without s | HTTP 200 + `subsonic-response status=error` code **40** — identical envelopes (no enumeration) |
| apiKey only | **error 40** — `apiKeyAuthentication[1]` is advertised but the param is never consulted |
| jwt only (no p/t) | **error 40** — guard requires u + (p or t); jwt-only never reaches the JWT branch |
| **Forged unsigned JWT + wrong password** | **200 OK** — SECURITY-CRITICAL: the jwt branch verifies NO signature; claims `sid`/`name`/`sub` map to a user. Knowing a username is sufficient to authenticate as that user. Must NOT be preserved (explicit security decision required — Phase 0 report risk R1) |
| Form POST auth | 200 (all endpoints register GET+POST) |
| Localhost/baseUrl bypass | Captured: no credentials needed when request is local OR host == `system.baseUrl` OR path contains `/images/`; **no user is synthesized** (BlankUserInfo downstream) |
| Podcast auth failure | **HTTP 403** + error 40 (unique to PodcastController; all others use HTTP 200) |
| `v`/`c` params | optional; no version check exists |

## 4. Envelope and format findings

- JSON envelope: `{subsonic-response:{status, version:"1.16.1", type:"Melodee", serverVersion,
  openSubsonic:true, ...}}`; XML default with **hardcoded lowercase `type="melodee"`**; JSONP
  `callback(json)` with `application/javascript`; `f=jsonp` without callback falls back to XML.
- **status:"ok" WITH an error block** on several not-found paths (getSong/getPlaylist unknowns);
  getArtist unknown → status:"ok" with NO artist key and NO error. Contrasted by the 302 class
  below.
- **Unknown-id 302 class:** getAlbum/getPlaylist/stream/download/createPlaylist/updatePlaylist/
  createShare with unknown or unprefixed ids throw inside services and the Blazor error pipeline
  answers **302** to `/Account/Login?ReturnUrl=%2FError...`. The ReturnUrl **embeds the original
  query string including auth credentials** — a credential-leak observation (captured with
  `followRedirects:false`; Location redacted in golden).
- XML quirks preserved: malformed `openSubsonicExtensions` elements (attributes with no element
  name), license JSON `trailExpires` typo (XML `trialExpires`), search2 hardcoded placeholder
  song fields (bitrate 0, suffix "mp3", path "unknown"), playQueue `current` is an internal
  **int PlayQueId** not a song id, Child `suffix` keeps the dot in JSON but strips it in XML,
  `starred` serialized as timestamp string, AlbumList2 `playedCount` vs `playCount`.

## 5. Streaming findings (13 golden steps)

- Full GET: 200, `Accept-Ranges: bytes`, `Content-Type: audio/wav`, `Content-Length`,
  `Content-Duration`, no-store cache headers, `Last-Modified`, `ETag "{size}-{ticks}"` (dropped
  at compare).
- **CRITICAL BUG — double range processing.** The 206 path wraps the file in a BoundedStream
  but leaves ASP.NET `EnableRangeProcessing=true`, so the Range header is applied a SECOND time
  against the bounded stream:
  - `bytes=0-1023` → 206 with correct bytes but **wrong Content-Range total** (`/1024`).
  - `bytes=100000-101023` → **416** (`Content-Range: bytes */1024`).
  - `bytes=100000-200000` → 206 with **ONE byte** (`bytes 100000-100000/100001`) — silently
    corrupted seek.
  - suffix ranges work only by coincidence (bounded length == suffix length).
  **Any nonzero-offset OpenSubsonic seek is broken at this baseline** while native-surface
  streaming is correct (EnableRangeProcessing=false there). MUST NOT be preserved; the Rust
  implementation must implement single-pass range handling (deviation sign-off required —
  Phase 0 report risk R2).
- Invalid/unsatisfiable ranges and `timeOffset` → **404 + error 70 JSON** (the 416 path for
  those is unreachable — the service re-wraps the error). `transcodeOffset[1]` is advertised
  but non-functional.
- **No transcoding exists** at this commit: `maxBitRate`/`format` are silently ignored (captured:
  full original WAV at 200). ffmpeg command strings exist only as seeded setting values.
- Unknown song id → 302 class (§4); known-song-missing-file would be 404 + error 70.
- `download`: 200 with `Content-Disposition: attachment; filename=...`; gated by
  `system.isDownloadingEnabled`.

## 6. Conditional features

- **Podcasts** (`podcast.enabled` seeded true): enabled state captured (empty lists; mutation
  attempts on missing ids → HTTP 400 with a **raw ResponseData body, NOT the subsonic
  envelope**). Disabled state captured in the dedicated phase (`legacy_oracle.py capture`
  toggles the setting): HTTP 400 + error 0 "Podcasts are currently disabled."
- **Jukebox** (seeded `jukebox.enabled=false`, empty `backendType`): **410** with empty body —
  the disabled AND enabled-without-backend states collapse to the same 410.
- **startScan/getScanStatus:** no admin requirement (any authenticated user); `startScan` →
  `scanStatus{scanning:true,count:0}` under `QuartzDisabled=true` (job fire failure is caught).
- **Melodee extension endpoints** (searchForArtist/searchForArtistImage/searchForAlbumImage,
  advertised `melodeeExtensions[1]`): **302** in the fixture environment (external provider
  dependency). Environment-conditional evidence recorded; matrix "Supported" claim noted.

## 7. Playlists/bookmarks/queue/shares/radio

- getPlaylists/getPlaylist shapes with `dpl_` dynamic-playlist merge, allowedUsers, owner.
- **Playlist serialization is cover-dependent and fragile.** `createPlaylist` with a
  cover-bearing first song works (200); `updatePlaylist` on a playlist whose cover song's album
  lacks artwork **302s** (cover resolution throws during response serialization; mutation NOT
  applied). In the pre-artwork fixture, even create 302'd after PARTIALLY creating the playlist
  (SongCount set, no PlaylistSong rows, null SongId), and the poisoned row then broke **all**
  playlist serialization endpoints (500 class) until cleaned. The service create itself
  (`CreatePlaylistAsync`) is correct; the fragile boundary is cover resolution. MUST NOT be
  preserved.
- deletePlaylist works; deleted playlist → 200 status:"ok"+error70 quirk (vs 302 for the
  all-zero GUID).
- Bookmarks CRUD round-trips; position unit is inconsistent (controller doc ms, model doc
  seconds; raw value preserved).
- savePlayQueue/getPlayQueue round-trips; `current` quirk recorded (§4).
- Shares CRUD round-trips (admin); share URL `{baseUrl}/share/{unique}` (origin aliased);
  updateShare/deleteShare by `share_{guid}`.
- Internet radio CRUD round-trips (admin-gated mutations, `radio_{guid}` ids).
- getUser supported; **createUser succeeds for fresh usernames** (200 + user model) and returns
  error 10 "User creation failed." for duplicates (corrected by the clean-recreation gate — the
  initial error-10-only observation came from an accumulated database).

## 8. Browsing and catalog semantics

- Full browse path captured over the fixture catalog: indexes, ID3 artists, artist detail
  (incl. normalized-name collision pair as distinct identities), album detail with
  **OpenSubsonic-rich fields** (contributors with nested `artistId3`, artists[]+albumArtists[]+
  displayArtist/displayAlbumArtist, genres[] + singular genre, replayGain, isCompilation,
  discTitles, ItemDate forms), multi-disc (disc-qualified numbers, discTitles), minimal-metadata
  null behavior, directory browse, album/artist info (offline providers), similar/top songs.
- **getTopSongs artist=Dune merges both collision artists** (two entries, artist shown as
  "Dune" for both) — name-based lookup cannot distinguish the identities.
- Lists: albumList (legacy) + albumList2 types (newest/alphabetical/byGenre/byYear/starred/
  frequent/recent — **`recent` sorts by ReleaseDate, not last played**); randomSongs (masked
  array, envelope contract); songsByGenre incl. Unicode genre; starred/starred2 with the
  literal placeholder `artistImageUrl:"URL"` quirk.
- Search2/3: collision query, Unicode query, empty-result shapes; search3 envelopes
  (`searchResult3` with album/song/artist arrays).
