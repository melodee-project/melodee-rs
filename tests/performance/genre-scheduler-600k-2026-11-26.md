# Concurrent genre import and scheduler sample — 2026-11-26

Reproduce with `python3 scripts/perf_representative.py -- python3 scripts/perf_genre_scheduler.py --releases 200 --timeout 900 --temp-parent .local-dev`. The harness creates and deletes a UUID-owned PostgreSQL database and media tree. Raw sanitized observations: [genre-scheduler-600k-2026-11-26.log](genre-scheduler-600k-2026-11-26.log).

The seeded catalog contained 35,000 Artists, 50,000 Releases and 600,000 Tracks; seed creation took 179.6 s. The workload generated 200 valid five-second, single-Track Releases (MP3 and FLAC), all with the same new genre; 12,594,640 input bytes. The production server was an operator-supplied release binary (SHA-256 `9d7b9aafa85f0708b1eefd915c02a21dfb4dfd90686b8c0b087ddd2044bdbc13`); its source identity was not independently verified. Harness HEAD was `08de08d50cb1be6e76c66000232dae257c1a2d2f` with tracked changes. This is not a comparable before/after run.

All 200 work items reached cataloged in 62.518 s including startup and polling: 191.946 Releases/min and 3.199 Tracks/s. On both `native` and `opensubsonic` surfaces, aggregate counts exactly matched authoritative term queries: 200 Releases and 200 Tracks. Ready-to-first-claim latency over 200 work items was p50 12.814 s, p95 23.025 s, maximum 24.444 s. Log parsing observed 200 claimed items in each of inspection, normalization, validation, publication and catalog, with respectively 64, 66, 58, 60 and 57 idle passes; this includes the post-completion idle interval.

In 234 samples at nominal 250 ms, both total database lock waiters and advisory lock waiters peaked at three and were nonzero in 72 samples. Sampled lease maxima were two each for inspection, normalization, validation and publication, and four for catalog. These are sampled states, not continuous utilization, lock duration, or proof of fairness. Server CPU time was 7.19 s and peak RSS 48,492 KiB; these exclude child processes.

Host: AMD Ryzen 9 3900X, 24 logical CPUs, 65,727,588 KiB memory, Linux, btrfs (4 KiB allocation unit); PostgreSQL 18.3, max_connections 100, shared_buffers 128 MB, work_mem 4 MB. Worker concurrency was configured to two per stage. Cache condition was uncontrolled. Search, policy, discovery, enrichment, podcast and interactive workloads were disabled. Source generation was excluded; the separate discovery scheduler is not covered by this measurement. One-track synthetic releases, no slow clients and no competing interactive workload limit generalization.
